# Catalog data notes

How to read (and safely edit) the fields in `src/data/shoes.ts`.

## Field semantics

| Field | Meaning | Values |
|---|---|---|
| `archSupport` | **The arch profile the shoe suits — not how much support it contains.** | `low` = flat / low arches (structured shoes) · `medium` = normal arches (neutral trainers, racers) · `high` = high arches / supinators (soft max-cushion neutrals) |
| `stability` | Support structure built into the shoe | `neutral` · `stability` · `motion-control` |
| `cushion` | How the ride *feels*, not stack height | `firm` · `balanced` · `max` |
| `dropMm` | Heel-to-toe drop, brand spec unless noted | number |
| `weightG` | Approx men's US9, grams | number |
| `priceMyr` | Street / promo estimate in Malaysia, not RRP | number |

### The `archSupport` convention (important)

`recommend.ts` matches `profile.arch` (the runner) directly against `shoe.archSupport`, so
the field must describe **who the shoe is for**:

- flat / low arch → tends to overpronate → **structured** shoes (`archSupport: 'low'`)
- high arch → tends to supinate, absorbs less shock → **soft neutral** shoes (`archSupport: 'high'`)
- normal arch → neutral daily trainers and racers (`archSupport: 'medium'`)

The current values are generated by one rule, so new entries stay consistent:

```
stability !== 'neutral'  ->  'low'
cushion   === 'max'      ->  'high'
otherwise                ->  'medium'
```

> Before 2026-08, this field held the *amount* of support instead, which inverted the 25%
> arch axis: flat-footed runners were pushed toward carbon racers and high-arch runners
> toward motion-control shoes. Fixed by re-mapping all entries — see git history.

## Calibration status

| Brands | State |
|---|---|
| Nike · ASICS · adidas | Calibrated earlier from lab/review sources |
| **Brooks · New Balance · Xtep** | **Calibrated 2026-08** — drop, weight, cushion/stability class, summaries |
| HOKA · Saucony | Global score calibration only — specs not individually re-checked |

### What changed in the Brooks / NB / Xtep pass

Corrections worth knowing about (published spec vs. what the catalog previously claimed):

- **Ghost 17** — 10 mm drop, not 12; ~290 g, not 275
- **Glycerin 23** — 8 mm drop (DNA Tuned platform lowered it from 10); ~300 g
- **Launch 12** — 8 mm drop, not 10; ~249 g
- **Cascadia 19** — 6 mm drop; re-classed `neutral` (trail shoes are neutral platforms)
- **880v15** — 6 mm drop, not 10 — the v15 moved to a 40.5/34.5 mm platform; ~300 g
- **860v14** — 8 mm drop, not 10
- **1080v15** — ~262 g, not 280 (new Infinion foam is ~20 g lighter than v14)
- **Rebel v5** — cushion `balanced`, not `firm`; ~225 g
- **SC Elite v5** — 8 mm drop, not 4 (v5 raised it from the v4's 4 mm); ~224 g
- **Hierro v9** — 4 mm drop; re-classed `neutral`
- **Propel v5** — cushion `balanced`, not `firm`; best at steady paces, not tempo
- **Arishi v5 / 680v8** — 8 mm drop
- **160X 5.0 Pro / 3.0 Pro** — ~4 mm drop, not 8; both heavier than listed (235 g / 255 g)
- **2000km 2.0 & 3.0** — cushion `balanced`, not `max`
- **One Piece 2.0** — cushion `firm` (nylon-plated workout shoe, not an easy-day trainer)

Xtep publishes limited data for the domestic 2000km / One Piece models; those entries say so
in their highlights rather than implying lab precision.

## Known catalog gaps

- **No budget-priced stability shoe.** An overpronating beginner on a budget currently matches
  RM 589–649 shoes. Something like the ASICS GT-1000 13 (~RM 429) would close it.
- HOKA and Saucony entries have not had a spec-by-spec review.

## Adding or removing a shoe

1. Edit `src/data/shoes.ts` only — add or delete an `s({ ... })` block.
2. Add the photo at `public/shoes/{id}.jpg` (filename must equal the `id`).
3. Set `archSupport` using the rule above.
4. `npm run build` to confirm, then commit.

Scoring and pages need no changes for normal catalog edits.
